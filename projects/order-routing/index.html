Omnichannel order routing

I built an order-sourcing engine that decides how each online order gets fulfilled: picked up in store, delivered same day from a nearby store, shipped from a store, shipped to a store, or shipped from the warehouse.

Personal project, built on my own time. It is not affiliated with, endorsed by or based on the code or data of any employer. Everything runs in your browser on sample data generated from a seeded random number generator, and all stores, products and figures are invented.

    How it works

    Every store and the warehouse holds stock for 25 products, a safety-stock level and a daily picking capacity. What a node can promise is its available-to-promise quantity: on hand, minus units already reserved, minus safety stock.

    For each order I build every way of assigning its lines to nodes that pass the hard checks: enough available-to-promise stock and picking capacity left. A plan counts as pickup today only if the chosen store has every line, and as same day only if one store inside the radius has every line.

    Each plan gets a cost. Distance, how full the node would be, and how much of its sellable stock the order would use are weighted by the sliders. A split adds points per extra parcel and a missed pickup or same-day promise adds . The cheapest plan wins and its stock is reserved before the next order is routed.

    The fallbacks come out of the same scoring. If the pickup store is short, the order ships to that store from another node. If no single node has every line, the split penalty keeps the number of parcels low. Lines nobody can supply are backordered.     What this shows

    Online demand and store inventory are usually planned apart. This demo shows how I think about joining them: treat every store as a small fulfilment node, be strict about what each one can really promise, and make the trade-offs between speed, cost and store workload explicit and adjustable. It is a simplified model I wrote to explain the idea, with no connection to any employer's systems.
